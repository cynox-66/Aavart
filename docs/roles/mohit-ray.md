# Mohit Ray: Design and Assets

## Own

- Visual hierarchy, layout, colors, typography, icons, and demo assets.
- Clarity of schedule state, risk, reasons, locks, approval, and export guardrails.

## Must implement

- Make unsafe or unavailable actions visibly distinct.
- Prioritize schedule readability over decorative visuals.
- Keep terminology identical to the shared contract.
- Supply assets in formats the frontend can load locally.

## Must not implement

- Visual claims of live system integration.
- Decorative complexity that hides status or reason codes.
- New labels that conflict with canonical statuses.

## Done when

The presenter can explain the plan, conflict reason, lock state, and approval state without relying on hidden knowledge.
